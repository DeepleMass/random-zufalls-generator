# bitsequences - Rust implementation of the paper

Implementation of the paper *The Evaluation of Finite Bit Sequences*
(reference: `EvaluationOfFiniteBitSequences.pdf` in the repository
root) in Rust. The project is a Cargo workspace:

```
bitsequences/          core library + three CLIs
bindings/python/        Python bindings (PyO3, module name `bitsequences`)
examples/example.py     using the bindings from Python
Makefile                build, test, build and install the Python wheel
```

## Command-line tools

### `evaluate` - evaluate a data set (paper Section 5)

    cargo run --release --bin evaluate -- <directory>

The files are concatenated name-sorted (= chronologically for
timestamp file names) into a single bit sequence; runs continue
across file and block boundaries. Output: table of the cumulated
frequencies with logarithm and expectation, chi-square test
against the geometric distribution, and estimated transition
probability.

### `deviation` - measure how far a file deviates from the target

    cargo run --release --bin deviation -- [--full] <file>...

Each file is read as a bit sequence. The tool prints the
**deviation score** (chi-square per degree of freedom against the
geometric distribution; ~ 1.0 matches the paper's target, larger
values are structured) and a **ranking** (closest to the target
first). With `--full` the per-length deviation distribution is
printed as well.

Empirical ranking (from high to low entropy):
encrypted ≈ random (1-2) < zip (40) < text (100000+).

### `extract` - produce a sequence with the paper's exact distribution

    cargo run --release --bin extract -- [--text] <target_bits> <source|-> [output|-]

Reads an entropy source (file or stdin via `-`), decomposes it into
runs, accepts each run the target distribution still needs, and
silently discards the rest, until the target is fulfilled. The
output has by construction exactly the paper's prescribed
distribution. Output is packed raw bytes (MSB first); `--text`
gives a human-readable 0/1 string.

Status messages go to stderr; stdout carries only the data.

### `dump` - inspect binary data in human-readable form

    cargo run --release --bin dump -- [--bits] [--runs] [<file>|-""]"

Reads binary data (file or stdin) and prints:
- **Hex dump** (always): address, 16 hex bytes per line, ASCII art (like `xxd`)
- **`--bits`**: additionally the bit string (0/1, MSB first per byte)
- **`--runs`**: additionally the run-length analysis (cumulated
  distribution, deviation score, expected values)

This is the companion tool for inspecting the binary output of
`extract` without needing the `--text` flag.

### Unix pipelines

The three tools compose into pipelines:

```bash
# Extract entropy from an encrypted file and store as binary
openssl enc -aes-256-cbc -in source.txt -pass pass:secret | extract 4096 - result.bin

# Or directly from /dev/urandom
dd if=/dev/urandom bs=1024 count=10 2>/dev/null | extract 4096 - result.bin

# Verify the result (deviation score should be near 0)
deviation result.bin

# Full chain: encrypt → extract → inspect
openssl enc -aes-256-cbc -in source.txt -pass pass:secret \
  | extract 1024 - - \
  | dump --runs

# Or: extract → hex dump for visual inspection
extract 1024 entropy.bin - | dump
```

## Building and testing (Makefile)

    make build       # debug build of the workspace
    make release     # release build (default target)
    make test        # all tests: examples, lemmas and theorems of the paper
    make check       # cargo check without artifacts
    make doc         # build the HTML reference documentation

The tests in `bitsequences/tests/paper_tests.rs` verify, among
other things, the base distribution theorem (N = 2..16), the
construction lemma, both identities, the composition example
B = 341, the cardinality formula for N <= 4 (complete enumeration)
and the ordering claims about B_5. Every public item additionally
carries an executable doctest; `cargo test --doc` runs all 26 of
them, so the documentation itself is tested.

## Embedding in Python

The library is available as the Python module `bitsequences` via
PyO3 (prerequisite: `brew install maturin`):

    make python-install      # build the wheel and install it user-wide

(Variant for virtual environments: `make python-venv`.)

Then in Python:

    import bitsequences
    bitsequences.base_distribution_from_cumulated([16, 8, 4, 2, 1])  # [4, 2, 1, 0, 1]
    bitsequences.iterative_generator(7)
    bitsequences.is_member([...], 7)
    bitsequences.composite_frequency(341)  # [86, 42, 22, 10, 6, 2, 2, 0, 1]
    bitsequences.deviation_score(histogram)

For large amounts of data, `run_histogram_from_bytes(data)` accepts
raw `bytes` directly (most significant bit first per byte; runs
cross block boundaries) and returns the run histogram;
`cumulated_distribution_from_histogram` completes the evaluation.
During byte processing the Python interpreter is released
(GIL-free). A complete example: `python3 examples/example.py`; all
doc comments appear in `help(bitsequences)`.
